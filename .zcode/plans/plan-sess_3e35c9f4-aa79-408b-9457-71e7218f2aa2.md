# 粗筛召回质量测试计划

## 🎯 测试目标

测试从大量历史消息（300+条）中召回与当前问题最相关消息的效果。

## 📊 测试场景设计

### 模拟真实长会话
```
历史对话 300 条消息，包含3个不相关话题：
├─ 消息 0-99:   React 开发 (useState, useEffect, 性能优化)
├─ 消息 100-199: Python 数据分析 (pandas, numpy, matplotlib)  
└─ 消息 200-299: Docker 部署 (Dockerfile, docker-compose, 优化)

测试查询 5 个：
1. "How to prevent unnecessary re-renders in React?" (应召回 0-99)
2. "Complex state logic with useReducer in React" (应召回 0-99)
3. "Group and aggregate pandas DataFrame" (应召回 100-199)
4. "Reduce Docker image size best practices" (应召回 200-299)
5. "React hooks lifecycle explained" (应召回 0-99)
```

## 🔍 测试策略

### 策略1: 纯向量相似度
- 用 sentence-transformers 向量化
- 计算 cosine similarity
- 按分数排序

### 策略2: 纯关键词匹配
- 提取 query 关键词
- 计算 Jaccard 相似度
- 按重叠度排序

### 策略3: 混合策略
- 0.6 × 向量相似度
- 0.4 × 关键词匹配
- 综合排序

### 策略4: 向量 + 时间衰减
- 0.7 × 向量相似度
- 0.3 × 时间权重（越新越高）
- 测试是否会过度偏向新消息

## 📈 评估指标

- **Precision@K**: 召回前K条中相关消息的比例
- **MRR**: 第一个相关结果的排名倒数（越高越好）
- **召回耗时**: 实际执行速度
- **Top-5 可视化**: 展示实际召回的消息

测试 K = [10, 20, 50]

## 🎯 成功标准

- Precision@50 > 80%（前50条中至少40条相关）
- MRR > 0.5（第一个相关结果排在前2位）
- 召回耗时 < 200ms（300条消息）

## 📦 实施步骤

1. 生成 300 条跨3个话题的测试消息
2. 创建 5 个测试查询
3. 用 4 种策略进行召回
4. 计算 Precision@K, MRR 指标
5. 可视化 Top-5 召回结果
6. 生成汇总报告
