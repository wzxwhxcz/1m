# 用户前台面板 + Linux Do OAuth + 后台配置 实施计划

## 📋 需求确认

### 核心需求
1. **Linux Do OAuth 登录**：用户通过 Linux Do 授权登录
2. **自动生成 service_key**：首次登录自动创建账户并分配 sk-xxx 密钥
3. **用户面板功能**：
   - 配额使用统计（今日用量/总配额、趋势图）
   - API 密钥管理（查看/复制/重置 service_key）
   - 套餐信息（当前套餐、trust_level、升级说明）
   - 请求日志（历史调用记录）
4. **管理后台配置**：
   - OAuth 配置（CLIENT_ID、CLIENT_SECRET、REDIRECT_URI）
   - 默认套餐规则（基于 trust_level 自动分配 + 统一 Free）
   - 环境变量管理（所有配置项可视化）
5. **API 调用方式修改**：
   - 从 `x-service-key` header 改为 URL 路径嵌入
   - 支持动态上游 URL（用户可指定不同的 API 提供商）

### 设计风格

- **管理后台**：深色主题（#0F1117 + #5B8CFF）- 已完成

## 🏗️ 架构设计

### 路由结构
```
/admin/*              → 管理后台（深色）
  /admin/login        → 管理员登录
  /admin/dashboard    → 仪表盘
  /admin/users        → 用户管理
  /admin/settings     → 系统配置（新增）
  /admin/oauth        → OAuth 配置（新增）
  
/user/*               → 用户前台（白蓝）
  /user/login         → 跳转到 Linux Do OAuth
  /user/callback      → OAuth 回调处理
  /user/dashboard     → 用户仪表盘
  /user/api-keys      → API 密钥管理
  /user/logs          → 请求日志
  /user/plan          → 套餐信息
```

### 认证流程

#### 管理员认证（已完成）
```
用户输入 admin/admin123 
→ POST /api/admin/login 
→ 返回 JWT token 
→ 存储到 localStorage
→ 访问管理后台
```

#### 用户 OAuth 认证（新增）
```
1. 用户点击"使用 Linux Do 登录"
   → 跳转 https://connect.linux.do/oauth2/authorize?client_id=...&redirect_uri=...

2. 用户授权后回调
   → GET /user/callback?code=xxx
   → 前端提取 code，调用后端

3. 后端处理
   → POST /api/user/oauth/callback { code }
   → 后端用 code 换 access_token
   → 调用 Linux Do API 获取用户信息
   → 检查数据库是否已存在（通过 Linux Do user_id）
   → 不存在则创建用户：
      - 生成 service_key: sk-{timestamp}-{random9}
      - 根据 trust_level 分配套餐
      - 插入 users 表
   → 返回用户 JWT token

4. 前端存储 token
   → localStorage.setItem('user_token', token)
   → 跳转 /user/dashboard
```

## 📡 API 端点设计

### 用户端 API（新增）

#### 1. OAuth 回调处理
```
POST /api/user/oauth/callback
Body: { code: string }
Response: { 
  token: string,
  user: {
    id: number,
    service_key: string,
    username: string,
    email: string,
    plan: string,
    quota_daily: number,
    trust_level: number
  }
}
```

#### 2. 获取当前用户信息
```
GET /api/user/profile
Headers: Authorization: Bearer {user_token}
Response: {
  id, service_key, username, email, plan, quota_daily, 
  quota_used_today, trust_level, avatar_url, created_at
}
```

#### 3. 重置 API 密钥
```
POST /api/user/api-key/reset
Headers: Authorization: Bearer {user_token}
Response: { new_service_key: string }
```

#### 4. 用户请求日志
```
GET /api/user/logs?page=1&page_size=20
Headers: Authorization: Bearer {user_token}
Response: {
  total, data: [
    { id, created_at, upstream_url, input_tokens, output_tokens, 
      recall_triggered, total_latency_ms, status }
  ]
}
```

#### 5. 配额使用趋势
```
GET /api/user/quota/trend?days=7
Headers: Authorization: Bearer {user_token}
Response: {
  data: [
    { date: '2026-08-01', used: 45, quota: 100 },
    ...
  ]
}
```

### 管理端 API（新增）

#### 6. 获取系统配置
```
GET /api/admin/config
Headers: Authorization: Bearer {admin_token}
Response: {
  oauth_client_id, oauth_client_secret, oauth_redirect_uri,
  default_plan_free, default_plan_trust_0, ...
}
```

#### 7. 更新系统配置
```
PUT /api/admin/config
Headers: Authorization: Bearer {admin_token}
Body: { key: string, value: string }
Response: { success: true }
```
