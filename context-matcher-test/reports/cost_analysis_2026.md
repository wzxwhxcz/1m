## 📊 完整架构成本计算

### 推荐架构
```
用户请求 (1M tokens上下文)
    ↓
【第一层：粗筛 - CAR】
  输入: 1M tokens历史消息
  输出: 100条相关消息 (~100K tokens)
  成本: 几乎为零（本地向量计算）
  耗时: ~50ms
    ↓
【第二层：精排 - 便宜LLM】
  输入: 100K tokens候选 + 系统提示
  输出: 精选50K tokens上下文
  成本: LLM API调用
  耗时: ~2s
    ↓
【最终模型：400K限制模型】
  输入: 50K精选上下文 + 用户查询
  输出: 最终回答
  成本: 按最终模型定价
```

## 🔧 成本优化技巧

### 1. Prompt缓存 (节省36-75%)

**Gemini Prompt Caching**:
```python
# 系统提示和粗筛结果可以缓存
cached_input = """
<system>精排任务提示...</system>
<candidates>100条候选消息...</candidates>
"""

# 缓存价格: $0.025/1M (正常$0.10/1M)
# 节省: 75%
```

**适用条件**:
- 系统提示固定
- 粗筛候选格式标准化
- 缓存命中率 > 50%

**实际节省**: 36% (假设70%输入可缓存)

---

### 2. 智能路由 (节省20-30%)

**策略**: 根据查询复杂度选择模型

```python
def route_model(query, candidates):
    complexity = calculate_complexity(query, candidates)
    
    if complexity < 0.3:
        return "deepseek-v3.2"  # 简单查询，最便宜
    elif complexity < 0.7:
        return "gemini-flash-lite"  # 标准查询
    else:
        return "gemini-2.5-pro"  # 复杂查询，贵但准
```

**预期分布**:
- 30% DeepSeek ($0.017)
- 60% Gemini Flash Lite ($0.014)
- 10% Gemini Pro ($0.45)

**加权成本**: $0.016 (vs 全用Flash Lite的$0.014，略贵14%但质量更好)

---

### 3. 批处理 (节省10-20%)

**适用场景**: 非实时查询

```python
# 累积100个查询，批量调用
batch_requests = [
    {"input": query1, "candidates": cand1},
    {"input": query2, "candidates": cand2},
    # ... 100个
]

# 批量API通常有折扣
response = gemini_batch_api(batch_requests)
```

**折扣**: 10-20% (需与供应商谈判)

---

### 4. 动态K值 (节省输入token)

**策略**: 根据查询复杂度动态调整粗筛返回数量

```python
# 简单查询：只需50条候选 (~50K tokens)
# 复杂查询：需要100条候选 (~100K tokens)

if is_simple_query(query):
    candidates = car_retrieval(query, k=50)
    # 输入成本: 52K × $0.10/1M = $0.0052
else:
    candidates = car_retrieval(query, k=100)
    # 输入成本: 102K × $0.10/1M = $0.0102
```

**节省**: 20-40% (假设50%查询是简单查询)
