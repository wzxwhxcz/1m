## 💡 新方案：分层上下文构建

### 核心思路：**原文优先 + 分层压缩**

```
1M历史消息
    ↓
【CAR精准召回】
召回100条最相关消息
    ↓
【智能分层】
    ├─ Tier 1 (Top 30-50): 完整保留原文 ✅
    ├─ Tier 2 (31-60): LLM压缩摘要
    ├─ Tier 3 (61-100): 索引（标题+标签）
    └─ Global: 全局摘要
    ↓
【最终400K模型】
- 核心消息: 完整细节，不丢失信息
- 相关消息: 压缩背景，节省空间
- 扩展索引: 可追溯，知道还有什么
- 全局视角: 理解整体脉络
```

## 🎓 技术实现细节

### Tier 1: 完整保留策略

```python
def build_tier1(candidates, budget=150000):
    """Tier 1: 完整保留最相关的消息"""
    tier1 = []
    used = 0
    
    for msg in candidates:
        tokens = estimate_tokens(msg["content"])
        if used + tokens <= budget:
            tier1.append(msg)  # 完整保留
            used += tokens
        else:
            break
    
    return tier1  # ~30-50条完整消息
```

**关键点**：
- 按相关性排序（CAR已排好）
- 贪心策略：尽可能多地保留
- 完整原文，不做任何修改

### Tier 2: 智能压缩策略

```python
def compress_tier2(messages):
    """Tier 2: 压缩但保留关键信息"""
    
    # 按主题分组
    groups = group_by_topic(messages)
    
    compressed = []
    for topic, msgs in groups.items():
        # 提取关键信息
        summary = f"{topic}相关讨论({len(msgs)}条)：\n"
        
        # 保留关键代码片段
        code_snippets = extract_code(msgs)
        if code_snippets:
            summary += "关键代码：\n" + "\n".join(code_snippets[:3])
        
        # 概括主要内容
        key_points = extract_key_points(msgs)
        summary += "\n要点：" + "；".join(key_points)
        
        compressed.append(summary)
    
    return "\n\n".join(compressed)
```

**关键点**：
- 按主题分组总结
- 保留关键代码片段（不要全丢！）
- 提取要点而非流水账
- 压缩比 ~70%（30条 → 相当于10条的信息量）

### Tier 3: 索引生成策略

```python
def create_tier3_index(messages):
    """Tier 3: 创建可追溯索引"""
    index = []
    
    for i, msg in enumerate(messages):
        # 提取标题（前50字符）
        title = msg["content"][:50].strip()
        
        # 自动标签
        tags = extract_tags(msg["content"])  # #react #performance
        
        # 生成索引项
        index.append({
            "id": i + 1,
            "title": title,
            "tags": tags,
            "topic": msg.get("topic", "general")
        })
    
    return index
```

**关键点**：
- 不保留内容，只保留元数据
- 标题 + 标签，便于快速理解
- 非常节省tokens（每条 ~30 tokens）
- 模型可以"知道还有什么"
